Music

Your library shows locally imported tracks, playback availability, approval state and actions. Choose a library user at the top of the page; each user has separate audio and playlists.

  1. 1. Import

    Open Sources, add a YouTube or public Spotify playlist and optionally monitor it.

  2. 2. Listen

    Music is playable in Navidrome after its next library scan, even while a track waits for metadata approval.

  3. 3. Approve

    Go to Approval to confirm its MusicBrainz identity and metadata.

Two independent states: Audio availability and operation progress are different. Playable/AVAILABLE means audio exists; Missing/MISSING means a previously present file is absent. Queued, Running, Deferred, Waiting for approval, Failed, Stopped and Idle describe work states.

Approval

Cached names and background prefetch: Beets matches appear immediately; canonical MusicBrainz spellings and verified English aliases are filled from the shared persistent Catalogue cache. A background worker prefetches searches for every recording awaiting approval, including every stored Beets match and all results on each MusicBrainz search page. It also fetches credited artists once by MusicBrainz ID. This work survives restarts, uses the same shared MusicBrainz cooldown as normal searches and never changes music without your approval.

Progress & storage: The prefetch panel in Catalogue → Cache synchronization shows cached / discovered tasks, queued / total tasks, retrying items and the approximate saved Approval-cache data size. The physical Catalogue SQLite file also stores unrelated MusicBrainz graph data; its size appears in the detail line. The known total can increase when searches discover more candidates, so progress is not a fixed library-song count. MusicBrainz-wide HTTP 503 cooldowns pause the worker; individual lookup errors do not. Jobs have three normal-priority failed executions, then three back-of-queue executions before being disabled. The expandable failed-requests list has per-item Retry 3 times actions.

Clean unused cache: Use the two-step button in Catalogue → Cache synchronization to preview and remove obsolete prefetched search results and jobs. Data for locally approved music, its credited artists, MusicBrainz candidates awaiting approval, and searches associated with pending approvals is retained across all library users. The main Catalogue/Graph database entities, audio files, approvals and local metadata are never deleted. Cleanup reports the logical amount freed; the shared SQLite file may not immediately shrink on disk. Names in a currently open table may be re-fetched if they are no longer associated with pending music.

If a name is still missing, you can listen, compare the available characters and approve normally; metadata enriches as the background queue completes. A temporary MusicBrainz cooldown delays only background metadata, not Approval controls. Search page size is unchanged.

Approve one recording at a time. Current audio and its source appear on the left; Beets suggestions, MusicBrainz search and album-edition choices appear on the right.

Recording aliases versus pseudo-release titles: Some MusicBrainz recordings have a direct English recording alias. Others, such as a Japanese game soundtrack, have English track titles only on an English pseudo-release. Approval checks the exact recording IDs on those pseudo-release tracklists, shows the English name with a labelled source link, and keeps the original Japanese name on the first line. Pseudo-release titles do not change the recording ID or imply that this pseudo-release should be selected as an actual album.

Album editions: Recording-to-release lists are prefetched and stored persistently. Until the background query finishes, the picker says it is checking editions; it will populate automatically when the cache arrives. An empty completed list means MusicBrainz found no editions, not that the lookup is still queued. You can approve a recording without selecting an edition.

Official MusicBrainz spelling first: recording titles and artist credits show their exact canonical characters (including Japanese) on the first line and a known English alias or Beets display name just below. This makes it possible to read English while comparing the source video's native characters with MusicBrainz. Beets suggestions load exact-ID official spellings without changing your choice. When a name is unavailable, the interface says so rather than inventing a translation. Selecting Use keeps the exact MusicBrainz recording ID. Search relevance is not proof of an audio match.

Choose a specific album edition only when you know it is correct. A recording-only approval does not invent an album. You can retain original source tags, manually correct fields, or reject a wrong candidate; manually edited tags are protected from automatic Language updates.

Wrong matches and merged recordings

Use Review metadata to find the right artist and recording, or Original source metadata to undo a wrong name. If unrelated uploads were combined, separate the incorrect source URL from Sources & details. A protected currently-playing URL may need to be replaced before separating it.

Catalogue

Explore the shared public MusicBrainz cache: artists, recordings, album families, specific release editions and compositions. Cached entries are not necessarily downloaded.

Cache synchronization also displays Approval metadata prefetch progress, the queue and cooldown, cached data size and overall Catalogue database size. Expand Failed searches and metadata requests to inspect disabled jobs and retry each for three more low-priority attempts. Use Clean unused cache to preview removing obsolete searches while retaining metadata for already approved music and recordings still awaiting approval. Music and Catalogue graph entities are never deleted.

Search cache uses saved metadata; Search MusicBrainz requests new data. Only items linked to my library filters by confirmed MusicBrainz IDs and their cached links, not similar names.

Index downloaded recordings synchronizes recording and credited-artist metadata in the background. It is metadata-only: it never edits or downloads audio. Use Refresh progress for the shared queue; its totals can grow as more relationships are discovered.

Album organization has moved to the dedicated Album tab. Catalogue is for exploring and synchronizing MusicBrainz metadata.

Album

Select local recordings, optionally include already-assigned recordings from across the library, and compare MusicBrainz release editions. Release groups are album families; specific releases are editions with potentially different tracklists.

Add more releases for an unmatched recording using the search field. Mark albumless recordings No Album Found if none is suitable; this is a reversible review decision, not a fake album audio tag. Existing assignments are preserved unless you explicitly choose a different release for that recording. The list can be paged and compared editions can be removed without losing planned assignments.

The final review shows each compatible change, unchanged or blocked recording, and exactly what will be queued. Audio changes use the same backed-up, reversible album-only jobs as the previous Catalogue organizer. The separate Artwork editor remains responsible for manual covers.

Language

Use Language to review and optionally update existing approved music. The global policy prefers an English alias for Title, Artist and confirmed Album where MusicBrainz provides one. No English alias means the canonical spelling remains. The original canonical names are kept in the ORIGINALTITLE, ORIGINALARTIST and ORIGINALALBUM Opus tags; their canonical names are not historical first editions.

  1. Review existing music. This reads file tags and compares them with the local MusicBrainz cache. It can take time on large libraries but never writes files. Possible name changes, original-tag repairs, no detectable changes and incomplete cache entries are counted separately. The counts are estimates: the worker checks authoritative MusicBrainz data again before applying.
  2. Choose an update scope. Select visible names only, or include missing/incorrect original-name tags. Tracks with no detectable difference are not selected. If cache metadata is incomplete, index the recordings from Catalogue, then review again.
  3. Apply to up to three tracks. Back up music, importer state and Navidrome first. The background worker changes tags, not audio content or MusicBrainz recording/release IDs. Stable paths remain unchanged; the importer retains original-file undo copies.
  4. Verify in Navidrome. After the library scan, check song IDs, favorites, ratings and playlists, then confirm this in Language. The bulk button remains disabled until the verified test matches the selected scope.
  5. Review individual name changes. The fixed-height scrollable list shows each current name, the proposed name and a Change button. The single Show meaningful changes only checkbox is enabled by default: it hides case-only, punctuation, diacritic, formatting and artist-credit separator changes, plus English-to-non-Latin fallbacks. Turn it off to see every proposal without rescanning. The same filter applies to the three-track test, Change all, and the Language bulk actions. A matching verified canary is required before bulk work, and original-tag-only entries stay separate. A meaningful difference is not proof that the proposed name is correct.
  6. Apply remaining. The page shows submitted/completed/failed counts; detailed errors, retries and track-level successes are logged under Activity.

Recheck already tagged names can include recordings marked english-first-v1 if MusicBrainz English aliases have since changed. This requires a new review and a matching three-track test. Busy, manually edited or unsafe files are excluded.

Reverse an accepted change: when the importer has a verified pre-change Opus backup and the track has not been edited since, the row's Change button becomes a light-red Reverse button. Reverse restores the exact previous audio tags, including the earlier display names and the language-policy marker, without changing recording IDs or audio paths. The restoration runs as a background job; details appear in Activity. If the backup is missing, ambiguous or the file was edited, reversal is unavailable.

Important: “Safe for review” never means that every title needs changing. A track with unchanged English names may need only original-name tags, or no update at all. Navidrome may not display custom ORIGINAL* tags without configuration.

Graph

Visualize artist, recording, release, album-family and work relationships. Downloaded library starts with confirmed local recording IDs; Entire cached catalogue may include music you do not own.

Filter node types, search names or focus on an exact MusicBrainz ID. Choose 180, 400 or 800 nodes per bounded request. Free physics lets connected nodes move naturally; Soft layers gently arrange them by graph distance rather than fixing each entity type in one column. Scroll over the canvas to zoom, drag to pan or reposition nodes, and use the node picker for keyboard access. Graph browsing never changes local files or identities.

Sources

Add a YouTube video or playlist, or a public Spotify playlist. Monitoring a playlist imports later additions. Spotify provides song metadata, not downloadable audio; the app finds a matching YouTube source and uses the same Approval process.

Open source details to inspect origins, playlist memberships, disabled URLs and source history. A disabled download URL stays blocked until explicitly re-enabled; existing audio is retained.

Optional Spotify connection and private playlists

Public Spotify playlists do not require an account connection. To connect supported account playlists, configure SPOTIFY_CLIENT_ID and SPOTIFY_REDIRECT_URI, then restart. Register this exact callback: https://YOUR-INGESTOR-HOST/api/spotify/callback.

Use HTTPS, or an explicit loopback IP for local development. Spotify development-mode rules and playlist ownership can limit which playlists are accessible. This is read-only access and does not modify Spotify.

Activity

Activity displays detailed importer, MusicBrainz, Beets, download and maintenance events, including Language review progress and per-track tagging results.

Disable Warnings and errors only to see INFO entries such as successful English tag updates. Follow latest keeps the log at its newest entry. Clearing the view does not delete stored server events.

Temporary provider errors (for example HTTP 503) may be followed by a successful retry. The operation's final success or failure is what matters.

Maintenance

Use Verify library to check missing files, track identities, tags and other integrity issues. Repair eligible tags preserves audio and confirmed IDs; unexpected asset hashes are excluded.

Updates and rollbacks for yt-dlp and spotDL affect future operations without replacing running audio files. Read recent Activity errors if a provider or worker operation fails.

Navidrome reads file and playlist changes on its next library scan. ReplayGain tags are preserved; enable playback normalization in your player if desired.
