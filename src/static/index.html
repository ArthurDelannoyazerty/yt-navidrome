From import to approval

YouTube and Spotify share the same download, identification and approval workflow. Follow the arrows to see what happens next.

Audio availability is separate. Playable means a local file exists, including temporary audio while you review it. Missing means an expected file needs redownloading; No audio means no local file is available. Retrying or replacing a track keeps existing audio playable until the replacement succeeds.

What do the statuses mean?

Two independent states: audio tells you whether a file is playable; the operation tells you what the app is doing.

English-first titles and original-script metadata

Global language policy: MusicBrainz aliases may be English translations, transliterations or commonly used English spellings. beets prefers an existing English alias for approved recording and artist names (and album titles of confirmed releases); it keeps canonical MusicBrainz names when no English alias exists. No machine translation is generated, and no per-user setting is needed.

Original names: the importer writes the canonical recording/artist/release names to the Opus/Vorbis fields ORIGINALTITLE, ORIGINALARTIST and ORIGINALALBUM when the corresponding identity is confirmed. These store the canonical MusicBrainz spellings, not the oldest historical performance or album. The usual TITLE, ARTIST and ALBUM tags are the preferred display names. Your player may need custom-tag configuration to show original-name fields.

Individual approval: choose a MusicBrainz recording using Use; its English-preferred name and canonical name are stored together. Use with a specific release to also assign an album. A recording-only approval never invents an edition or takes an arbitrary album; Unknown Album is expected until an edition is chosen.

Existing-library scan: Index downloaded recordings only updates the public MusicBrainz catalogue and does not retag or download audio. To apply English names to existing local files, open Catalogue → English-first names → Review existing-library English tagging. Back up your library, use Apply to first 3 tracks, check Navidrome song IDs, favorites, ratings and playlists, acknowledge the check, then explicitly queue the remaining eligible tracks. Recheck already tagged names only when you want to refresh names from updated English aliases. This uses copy-on-write, SHA checks and local undo copies. It skips busy music and manually edited metadata and never changes MusicBrainz identities or album assignments.

Album comparison: a reviewed exact release can supply an English title from an available cached alias, retaining its canonical title in ORIGINALALBUM. No English release alias means the canonical album title stays. Album-only edits do not select an alternate edition or re-download audio.

MusicBrainz Catalogue, local search and graph

Catalogue cache vs downloaded library: the catalogue stores public MusicBrainz artists, recordings, album editions, album families and compositions, including entries from online searches that are not downloaded. The Only items linked to my library checkbox (on by default) uses exact MusicBrainz IDs from locally approved recordings and their cached relationships; it never guesses from matching names. If a local artist or album is missing, choose Index downloaded recordings and wait for its relationships, or uncheck the filter to explore all cached entities.

Search cache reads stored entities; Search MusicBrainz fetches and caches online results. The same local-only filter applies to both searches. Select opens the chosen item in the right-hand panel. Drag Results height to change the scrollable list size without expanding the whole page. The selected item may include a tracklist, relations, cached metadata and a Show in graph action.

Sync / refresh on an artist queues its MusicBrainz lookup, credited recordings, release groups and works. Album-family requests can enqueue edition lookups and full tracklists. This is metadata only: it does not download audio or edit existing tags. Index downloaded recordings queues recording lookups and release associations for the selected library. Use Refresh progress to read the queue state; do not repeatedly force a refresh while it runs.

Progress: PENDING means waiting, RUNNING means being fetched, and COMPLETE means a catalogue request finished. The totals can increase during synchronization because discovered albums, editions and works create additional jobs. One background worker makes rate-limited requests, and these totals cover the shared catalogue queue, not the number of downloaded songs. The graph can be sparse until relationships are cached.

Music graph: Downloaded library starts from your confirmed recording IDs and their public MusicBrainz neighbors; Entire cached catalogue can include music you do not own. The graph is limited to 180 displayed nodes per request. Focus a MusicBrainz ID or search for a name to explore a different neighborhood; node type checkboxes only control visibility. Graph navigation never changes audio files.

Organize albums → Compare albums: select imported sources or individual track IDs to compare their known MusicBrainz recordings against cached releases. The suggested coverage is evidence, not automatic proof of the correct edition. Review an exact release, sync its tracklist if necessary, preview compatible changes, and confirm before applying album tags. Changes keep stable audio paths and can be undone from the album-change history.

Fix a wrong match or separate different songs

Use Review metadata to search MusicBrainz by artist and title, or choose Original source metadata to undo a wrong match.

If different uploads were merged, open Sources & details → Separate track on the wrong URL. Its playlist memberships follow the new entry, its audio is queued, and the rejected match is excluded from future suggestions.

The source of the current audio is protected. First Reprocess using the correct URL, then separate the other one. Remove & ignore origin instead excludes only that URL from future imports.

Spotify imports and optional connection setup

Paste a public Spotify playlist URL in Sources, just like a YouTube playlist. No Spotify account connection is needed for public imports. The app reads track metadata with spotDL, finds matching YouTube audio, then uses the normal downloader, beets identification and Approval tab. Spotify itself does not supply downloadable audio.

Monitor the playlist to scan new additions. The original Spotify link stays with each track, so you can filter music by source. If an automatic audio match needs help, use Link audio to choose a recording in your library or supply a YouTube video.

Optional account connection and private playlists

Create an app in the Spotify Developer Dashboard. Set SPOTIFY_CLIENT_ID and SPOTIFY_REDIRECT_URI in your server environment, then restart. A client secret is not required.

Register this exact callback: https://YOUR-INGESTOR-HOST/api/spotify/callback

Use HTTPS, or HTTP with an explicit loopback IP for local development. Spotify does not accept localhost. Development-mode apps require an eligible Premium app owner and allowlisted users. Playlist contents are available only for playlists you own or collaborate on.

This is read-only access. Music Ingestor does not modify your Spotify library. Each library user connects separately; keep this administration interface behind authentication.

Playback, discovery dates and administration

Navidrome sees changes on its next library scan. Temporary songs use the album Waiting for approval; approval moves them to their chosen album and updates exported playlists.

Discovery dates come from playlist additions or the first time a track was seen. They are saved in COMMENT and DESCRIPTION, separately from release dates.

Enable track ReplayGain in your player to use the measured loudness tags. Tag repair does not re-encode audio.

Each library user has separate files and playlists. These folders are not authentication: keep this administration app behind an authenticated reverse proxy.
