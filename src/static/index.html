How Music Ingestor works

From a source URL to a playable, user-separated library. No audio is re-encoded by tag repair.

The workflow

  1. 1Discover

    A video URL imports one video, even with a playlist parameter. Use a /playlist?list=... URL to import a playlist.

  2. 2Download to staging

    yt-dlp creates a candidate. Quota limits, retries and a shared YouTube circuit breaker protect the providers.

  3. 3Identify & review

    AcoustID and MusicBrainz supply candidates. Beets' native strong matches can proceed; ambiguous or changed identities need approval.

  4. 4Enrich & measure

    Beets applies release metadata, artwork and lyrics. Fresh loudness and true-peak measurements become playback tags.

  5. 5Activate & export

    The asset is committed and playlists are rewritten. Navidrome picks up file changes on its next scan.

One recording, many origins. The same video in several playlists is downloaded once per library user. Different uploads identified as the same recording share a logical track. If a full-album video was incorrectly merged with a song, open More → Technical details → Origins to Detach origin into a separate music row or Remove & ignore origin to keep it out of local playlists and future monitored imports. Neither action changes your YouTube playlist online. You cannot detach the origin supplying the current audio: first reprocess the track using the correct origin. Other users' libraries stay separate.

Two independent states

A song can be Available while its latest redownload is Failed. Health and operation counters overlap; they must not be added together. The counters describe the entire selected library, while the results line describes the current search and filter.

Audio health

UNAVAILABLE→AVAILABLE

Successful ingestion creates the current audio asset.

AVAILABLE→MISSING

An audit finds a missing or unsafe current file.

MISSING→AVAILABLE

Redownload restores audio. Tag repair cannot recreate a missing file.

Operation state machine

QUEUED→RUNNING→IDLE
NEEDS APPROVAL

Review a candidate → Approve → Queued. Approval is bound to the actual staged audio.

DEFERRED

Temporary provider failure → wait until the shown retry time → Running automatically. Existing staged audio is reused.

FAILED

Terminal error → inspect the reason → Retry or Retry all failed → Queued.

Each branch starts at Running. Delete removes the logical track; Delete and ignore also blocks its recording and origins. Interrupted cleanup remains in the durable queue.

Managing thousands of songs

Use the clickable global counters and the Unmatched identity, Integrity issues, or Needs approval filters to focus review. Export failures for an offline report. Retry all failed queues only failed operations, keeps provider pacing, and never touches approval or deferred work.

For existing files, run Verify library, inspect the paginated issues, then use Repair eligible tags. Repair recalculates loudness and restores discovery tags without downloading, moving files or changing musical identity. Unexplained hash changes, unreadable files and unsafe paths are excluded from batch repair. Check those separately rather than treating corruption as a normal tag change.

Approval is a decision, not a repair. Approve all accepts the top candidate for every waiting song in this library, including weak matches and identity changes. Review ambiguous songs individually when correct identification matters. Nothing automatically loosens beets' matching thresholds.

Discovery dates in Navidrome and Feishin

The Discovery column is the source history, not the release date or Navidrome's import date. Both COMMENT and DESCRIPTION contain the exact UTC timestamp. Technical details reads these values from disk, so you can distinguish a missing tag from a client that does not display it.

Navidrome imports the comment field, but available columns depend on the client and version. Current Feishin development sources call the comment column Note; older releases and some views may not offer it. A raw-tag inspector is useful when a client has no visible comment column. This application cannot add columns to another application's UI.

Loudness without modifying the audio

ReplayGain is playback metadata, not compression or permanent normalization. In Navidrome's personal options, select ReplayGain Mode → Use Track Gain and start with PreAmp 0 dB (labels vary by version). Scan the library after repairs, then reload or requeue the song so the player receives updated gain and peak values.

Opus R128 gain uses the standard −23 LUFS reference. Navidrome adds 5 dB for its ReplayGain playback reference. The ingestor also writes a measured true peak because Navidrome's web player skips gain adjustment when a peak is missing. No conflicting conventional gain tag is added, and no album gain is invented from a single song. Use Track Gain, not Album Gain, for this pipeline.

Clipping protection may reduce the boost for a very dynamic song. That is preferable to distorting the audio; perfect equal perceived loudness cannot be guaranteed without compression. Silent or invalid measurements fail rather than silently publishing misleading gain tags.

Why beets has auto: false

The adapter explicitly runs artwork, lyrics and loudness steps after identity selection. Disabling beets' automatic import hooks prevents duplicate processing; it does not disable these features. Artwork and lyrics are best-effort external lookups. Loudness analysis is required. Additional plugins are not enabled without a clear need because they add provider traffic and failure modes.

Correct a wrong recognition

Search MusicBrainz searches recordings by title and/or artist independently of the automatic shortlist. Switch to Artists and choose Show recordings to browse an artist, then Select recording and Apply selected recording. A confirmation is required; you do not need to copy an ID.

Restore source metadata is different from Keep current applied metadata. It removes a bad MusicBrainz identity and restores the retained source tags. Old imports without a raw-tag archive fall back explicitly to their retained provider title; missing album/date data is not guessed. You can also choose Use original source metadata while approving a candidate.

The correction dialog shows the latest recorded identification inputs and shortlist. Old imports have no retrospectively reconstructed report. Reprocess downloads fresh source audio and records new evidence. Direct corrections use the existing audio or pending candidate.

Why was this recording not recognized?

The automatic shortlist combines source text and acoustic fingerprint candidates. It is not an exhaustive MusicBrainz search. A recording can exist there without a matching AcoustID association, or differ in duration/version. Bulk approval can accept a weak candidate.
